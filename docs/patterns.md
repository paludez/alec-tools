# Tool patterns

- A tool with options and a preview has a caddy (see `bbox.ms` + `bboxCaddy.py`, `distribute.ms` + `distributeCaddy.py`): settings struct kept with lib/settings.ms, a session struct, preview with `undo off`, OK redoes it in one `undo "Name" on`, Cancel/close restores. The `.ms` holds the logic and small functions the caddy calls; the `.py` only builds the caddy. A click applies with the last settings, Shift+Click or a toolbar right click (`AlecTools_wantsOptions`) opens the caddy. The macro is one call, `AlecTools_runCaddyTool "<Section>" "<tool>.ms" "Alec<Tool>_run"` (lib/common.ms): a toggle that closes the open caddy (as Cancel) instead of starting again, so pressing the tool's button or shortcut again closes its caddy; a caddy with value boxes sets `KEY_TOGGLES = True`. The tool file still calls `AlecTools_closeCaddy()` on load and before a new session.
- Every caddy has a mini help: `add_help(HELP)` puts a small info icon at the right end of the title band (top right corner on a bare caddy; `help_icon(HELP)` to place it in a row instead), with the help as its tooltip. `HELP` is a module constant, `"\n".join([...])` of short lines (at most about 90 characters): one line per row or button saying what it does (`Name: ...`, the name turns bold; a continuation line is indented with four spaces), then what the mouse and keys do on the boxes (type a value or arithmetic + Enter, middle drag = ladder, right click = reset) and what OK / Enter, Cancel and the macro again do. Only what the code really does. Buttons and choices whose meaning is not obvious also get their own `setToolTip`.
- The Alec Tools toolbar is a Qt `QToolBar` on the Max main window (`tools/AlecToolbar.py`, created by `tools/toolbar.py` at the end of `AlecTools_load`; the field rows, also used by the Transform Popup, are in `tools/AlecToolbarFields.py`, the editor in `tools/AlecToolbarEditor.py`). Each button runs a macro (`macros.run "Alec Tools" name`) with the macro's own text and `iconName:`. The buttons, order, separators and looks are kept in `AlecTools.toolbar.json` in `getDir #userScripts` (defaults in `DEFAULTS`), edited with the Edit Toolbar macro (a right click on the toolbar opens nothing); the dock edge is in the ini. Buttons whose macro reads `AlecTools_wantsOptions()` are listed in `WITH_OPTIONS` (right click = options, corner triangle). Checked buttons and fields refresh on Max's own events (`tools/toolbarEvents.ms`: a NodeEventCallback for selection, transform and geometry, plus units and scene changes) and when the mouse enters the toolbar (Use Center has no event); no timer. Tests: `tests/toolbar_test.ms`.
- Every macro is one call into lib/common.ms (`AlecTools_runTool`, `AlecTools_runCaddyTool`, `AlecTools_toggleTool`, `AlecTools_switchTool` for Grab, Rotate, Scale, Transform Popup and Create Popup, which give way to each other: the open one is accepted, then the new one opens (their caddies know each other's shortcuts from Max's hotkey file, ToggleKey in lib/AlecTools_caddy.py, and take Enter or a left click in a viewport as accept and a right click as cancel, ViewportClicks); `AlecTools_runPython`), and the tool's entry is `Alec<Tool>_run`, the prefix spelled like the tool's name. Reload Alec Tools is the one exception: it must work when lib is broken.
- A tool that waits for a click (pickObject / pickPoint) runs it through `AlecTools_withPickTag text f`, so the bright tag shows in the viewport while it waits; the tag never closes a caddy.
- A tool that measures in the viewport is a `tool` started with `startTool` (see `measure*.ms`): the first click comes twice, skip `clickno == 2`; right click/Esc ends and clears.
- Status messages go to `displayTempPrompt` / `replacePrompt`, starting with the tool's name, in English like the rest of the UI. Lengths through `units.formatValue`.
- A macro gets an `iconName:` when the user wants one (find it with the Icon Browser macro); shortcut-only macros can go without.
- `audit.md` lists known problems and planned cleanups; strike through an item when it is done, and check it before adding a helper it already plans.
