# Verified in Max 2027

Facts checked in Max 2027 (add only what has been checked). Read the relevant ones before touching that area.

- `getDir #userScripts` and `getDir #userStartupScripts` exist.
- A parenthesized block is compiled before a `fileIn` inside it runs, so a function defined by that `fileIn` must be called with `execute "fn()"` from the same block.
- `sort` works on an array of strings.
- Names ignore case, and `name as string` gives the spelling Max met first in the session, not the one written: `#refraction as string` gave "Refraction". Put `toLower` on a name turned into text that is shown or compared.
- `convert` is a read-only system name: a local `fn convert` stops with "Cannot assign to read-only variable".
- `toolMode.commandMode` is `#pick` while a pickbutton picks. The Esc that cancels the pick shows in a 50 ms timer only after the mode has already left `#pick`.
- A global name used in a function binds to the global that existed when the function was compiled. After `globalVars.remove` (the purge) and a new definition, that function still sees the removed one (undefined). The core therefore calls lib functions by name: `(globalVars.get #name)()`.
- Edit Poly modifier: `SetSelection` returns true but the selection stays empty; use `modifier.Select #Vertex bits` (adds to the selection, the bits go in a variable because the argument is by reference) and `modifier.GetSelection`. `ConvertSelection #Face #Vertex` fills the vertex selection and keeps the face selection and the sub-object level. `modifier.MoveSelection delta` without `axis:` moves in world space; read positions back with `modifier.GetVertex v node:node` (world). Editable Poly: `polyop.moveVert node verts delta node:node` moves in world space.
- `nodeGetBoundingBox node frame` is tight on the evaluated geometry (modifiers included) in any frame and takes ~0 ms on 244k vertices. `node.min`/`node.max` is not tight on rotated objects.
- A camera from a USD stage is a `USDCameraObject` with a `USDXformableController`: `isProperty n #pos` and `isProperty n #scale` are false and reading `n.pos` stops with "Unknown property", while `n.transform` works (its axes had length ~100 on the one checked).
- Max saves every `macroScript` it loads as `<category>-<name>.mcr` in `getDir #userMacros` and loads that copy again at startup. A renamed macro therefore showed up twice (old copy + new). `AlecTools_load` deletes the `Alec Tools-*` copies before loading the macros, which Max then saves again. The stale entry stays in the running session until Max restarts.
- `intersectRayScene` does not hit back faces (a ray from inside a box finds nothing), and a ray that starts 100000 cm away hits nothing even with geometry on its path; from ~1000 cm it works. Its hit ray's `dir` is the surface normal.
- `intersectRayEx node ray` works only on Editable Mesh (gives `#(ray, face, bary)`); on a primitive, Editable Poly or a modifier stack it gives undefined. `RayMeshGridIntersect` (`Initialize 10`, `addNode`, `buildGrid`, `intersectRay pos dir false`, `getHitFace 1`) works on all of them, on the evaluated mesh, in world space, ~1-14 ms to build + cast on a box; its face index matches `snapshotAsMesh node`, whose verts are in world space and whose `getEdgeVis` marks the hidden diagonals.
- Layers: `LayerManager.newLayerFromName`, `layer.setParent`/`getParent` (undefined on a top-level layer)/`getNumChildren`/`getChild i`, `layer.addNode node`, `layer.nodes &arr`, and read/write `isHidden`, `isFrozen`, `renderable`, `wireColor` all work; `on` is the inverse of `isHidden`. `addNode` inside `undo on` is undone by `max undo`; it restores the layer the undo system last recorded, so a move done outside an undo context is skipped.
- macroScript `iconName:` takes a Qt resource icon in every form tried: short (`"MainUI/Snow"`, under `:/Icons`, no size or extension), full path (`":/Icons/MainUI/Snow_24.png"`) and a plugin's resource (`":/chaos/icons/show_layers.svg"`, V-Ray only). The Customize UI icon picker does not list Qt resources.
- Python: PySide6 6.8.3 and `qtmax.GetQMaxMainWindow()` are available.
- In a `tool` started with `startTool`, `on mousePoint clickno` fires twice for the first click (press = 1, release = 2, same point), then once per click (3, 4, ...).
- A `registerRedrawViewsCallback` function draws in every viewport with `gw.setTransform (matrix3 1)`, `gw.setColor #line`, `gw.polyline`, `gw.text` (world points), `gw.enlargeUpdateRect #whole`, `gw.updateScreen()`; the drawing stays in place when orbiting and goes with `unregisterRedrawViewsCallback fn` + `redrawViews()`.
- `viewport.getViewportFromScreenCoord [x, y]` (screen pixels) gives `#(panel, viewport index, id, hwnd, point inside the viewport, undefined)` for a point on a viewport; with `viewport.activeViewport` and `getViewSize()` it gives the active viewport's screen rectangle (`AlecTools_activeViewRect`). `getMAXWindowPos()` is in physical pixels, Qt's geometry in logical ones (equal at scale 1.0).
- `toolMode.axisConstraints` reads and writes Max's axis constraint (`#x`, `#y`, `#z`, `#xy`, `#yz`, `#zx`); a `tool` can read it on every mouse move, so F5-F8 work inside a running tool without reading keys.
- Max turns its shortcuts off while a widget given to `qtmax.DisableMaxAcceleratorsOnFocus(widget, True)` (or a child) has the focus, and on again at focus-out (C++ `QtHelpers::DisableMaxAcceleratorsOnFocus`). QLineEdit, QSpinBox, QDoubleSpinBox, QComboBox, QTextEdit and a few others get it on their own. It needs real focus: a QFrame with `grabKeyboard` gets no focus-in, so Max shortcuts (X, Y, Z, `-`) still ran. Letter keys on a panel go through a focused QLineEdit (`tools/grabCaddy.py`).

- **Do not call MAXScript from a Qt timer.** Observed: the toolbar's 250 ms QTimer calling MAXScript crashed Max after holding Esc in a viewport (Esc raises MAXScript's `SignalException`, which can escape through the Qt binding; the "interrupted" shows up in Max's own Scene Explorer `isChecked`). `escapeEnable = false` around the call and skipping ticks while Esc was down did not help; stopping the timer did. Refresh from Max's own callbacks (`NodeEventCallback`, `callbacks.addScript`) instead; a Qt timer may only run pure Python (e.g. Esc read from Windows with `AlecTools_caddy.escape_down()`). The same applies to a .NET timer. Also no event filter on the whole QApplication, only on your own widgets.
- Materials (property dump, `tests/converter_props_check.ms`; full names in the converter plan): `getPropNames` on a new `VRayMtl` lists only part of it (BRDF options, `texmap_*` with `_on`/`_multiplier`, `option_openPBRMode`) and leaves out the main parameters (diffuse, reflection, glossiness, IOR, ...). `OpenPBR_Material` has `emission_weight` (default 0, not in the OpenPBR spec), `emission_luminance` default 1000, maps as `<param>_map` + `_map_on`, and only `geometry_opacity_map` (no constant opacity). `ai_standard_surface` maps are `<param>_shader` + `_connected`. Physical's coat weight is `coating`, its thin film is in nm (default 555). Standard defaults: `Specular` 0.9 grey, `specularLevel` 0, `glossiness` 10.
- Lights (property dump, `tests/light_props_check.ms`): `Arnold_Light` `useColor`, `usePreset`, `useKelvin`, `useTexmap` are independent booleans for a script (setting one does not clear the others) and it has no `excludeList`. `VRayLight` `sizeLength`/`sizeWidth` are full sizes, `size0`/`size1` half sizes on a Plane (`size0` is the radius on a Disc or Sphere). `targetSpot()` and `VRaySun()` made by a script have `target` undefined. Setting `mesh_source` on a `VRayLight` keeps the source node, even with `mesh_replaceOnPick` on. `nodeGetBoundingBox` gives no usable box on a light. The sky map class is `ai_physical_sky`; `UberBitmap2.osl` is in `<maxRoot>\OSL`.
- `node.children as array` stops with "Unable to convert: #children() to type: Array"; collect them with `for c in node.children collect c`.
- Deleting the target of an `Arnold_Light` with `targeted` on deletes the light too.
- `VRayLight`: `multiplier` set before `normalizeColor` did not read back as set; set `normalizeColor` first. A node used as `mesh_source` cannot be linked to that light (Max shows "Cannot link: would create dependency loop"). `InstanceMgr.GetInstances` does not give the nodes in selection order.
- A new `Arnold_Light` made by a script starts with the values of the last one made in the session (`useKelvin` and `color` were seen), not with its defaults.
- Lights, Arnold GPU vs V-Ray GPU renders (`tests/lightConverter_scene.ms`, exposure control off): with Normalize off, a Quad, Disc or Point of gain G and a VRayLight in Default units with multiplier G match within a few percent, no factor of 2. Normalize on a Quad divides by its area in square scene units (cm) and matches. An Arnold Point or Spot with radius 0 and Normalize off renders nothing. Arnold's spot `aspect_ratio` 0.5 comes out wide along world X where Max's `aspect` 0.5 comes out tall along Y. An Arnold cylinder's axis lies along its local Y (seen by the user in the viewport against a Cylinder, not along Z). In Temperature mode a VRayLight's `color` reads as that temperature (3200 K: 255 175.7 76.5).
- A light's Shadows On checkbox is `node.baseObject.castShadows` (macro recorder); `node.castShadows` is the Object Properties flag of the node.
- VRayMtl fog: setting `refraction_fogDepth` changes `refraction_fogMult` with it (depth 2 read back multiplier 0.5, and setting the multiplier to 1 after the depth undid the depth), so the depth alone is the value. `VRayBlendMtl baseMtl:x coatMtl_0:y blend_0:c` leaves `coatMtl_0` / `blend_0` at their defaults: use the `coatMtl`, `Blend`, `texmap_blend` arrays.
